# Repository tools


- `check-home-touch.js` is a Playwright CLI run-code function that uses real Chromium touch input to long-press an assistant, checks that the menu backdrop intercepts outside taps, and confirms dismissal keeps home open.

- `capture-design.js` is a Playwright CLI run-code function that captures Today, assistants home, conversation, questions, approvals, failed/interrupted turns, assistant details and artifacts, assistant creation/settings, the Avatar editor, models/tools/skills, or profile Memory at desktop, tablet and phone widths. Pass `{ outputDir, prefix, screen, fixture }` with a matching `.agents/fixtures/*-design.json` to use the same populated data as the native design tour. It covers dark and large text, screen-specific empty and failure states, viewport overflow, conversation draft, clipboard and keyboard focus, and question answers or approval decisions with failure and retry. Recovery captures check draft preservation, refused and unconfirmed retries, request ID reuse and the interruption review gate.
- `npm exec tsx .agents/tools/check-memory-fixture.ts` verifies every Memory design fixture state against the production schema, digest rules and declared synthetic character-count delimiter.
- `python3 .agents/tools/capture-design.py SCREEN before|after --root ARTIFACT_DIRECTORY --origin LOOPBACK_ORIGIN --session OWNED_SESSION` runs `capture-design.js` with the matching shared fixture and saves its screenshots and JSON report. Use `--report NAME` to retain separate revision reports. It rejects incomplete conversation fixtures before browser launch, uses the installed CLI or pinned 0.1.22, and preserves the last good report if a run fails. Failed browser runs retain a diagnostic screenshot and page-error messages. Put the CLI that opened the session on PATH when reusing an npx-cached installation. Use `work after --work-case clear-confirmation` for the single-frame Clear spacing recheck. It verifies focus before the screenshot helper blurs it and requires zero writes. Use `work before --work-case tasks` for the full W2 BEFORE set. Use `work after --work-case tasks --task-gate a` for the W2a-only AFTER set, with the `work-tasks-a-after` report and its own screenshot directory. Use `work after --work-case tasks --task-gate b` for the separate 16-frame W2b task-editor tour. Each gate requires its own new `--report work-tasks-a-...` or `work-tasks-b-...` basename and refuses existing output. Combined W2 AFTER capture is not supported.
- `python3 .agents/tools/annotate-design.py SPEC.json OUTPUT.png` combines before/after screenshots with numbered pointers and matching notes. Requires Pillow. The specification has a `title` and `before`/`after` objects with `image` and `notes`, each note supplying `point` in pixels or `fraction` of image width/height, `text`, and an optional `offset`. `--batch MANIFEST.json` regenerates only listed comparisons, with relative `spec` and `output` paths under the manifest directory.

- `check-automation-browser.js` exercises goals, task creation/start and skill-diff review in the synthetic port-3021 preview at desktop and phone widths.

- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/check-native-release.mjs BUILD PRIVATE_RECEIPT` runs from the deployed Linux release to verify authenticated bootstrap, Hermes connectivity, the announced TestFlight build/link and exact service-worker bytes. It removes its temporary session and writes an owner-private sanitized receipt.
- `python3 .agents/tools/benchmark-native-markdown.py` compares fresh and cached native Markdown parsing with an optimized macOS executable; outputs CPU work timings, not iPhone scrolling measurements.
- `check-search-pointer-browser.js` is a Playwright CLI run-code function for the loopback preview on port 3017; verifies exact-message history requests, highlighting and scrolling at phone and desktop widths.

- `PREVIEW_LONG_TOOL=1 node .agents/tools/preview-app.mjs` shows short, long and unstructured tool-output fixtures for scrolling checks; combine with `PREVIEW_PRESENTATION=advanced` for raw tool details.
- `capture-ui-comparison.js` is a Playwright CLI run-code function that captures six desktop/phone states from the synthetic loopback preview. A wrapper can pass `{ outputDir, prefix }` as its second argument; defaults write to ignored `.private/ui-comparison`.
- `check-model-picker-browser.js` is a Playwright CLI run-code function that delays or blocks the actual model-picker chunk and verifies that text and voice controls remain uncovered at desktop and phone widths.

- `node .agents/tools/publish-ios.mjs setup|prepare|status|archive VERSION BUILD|upload VERSION BUILD|distribute VERSION BUILD` registers Apple identifiers, checks App Store profiles, archives and verifies the exact signed IPA, uploads it once, and confirms internal TestFlight availability before producing update settings. Uses private Mac credentials in `~/.config/wildbots/apple/config.json`; see `ios/README.md`. `apple-api.mjs` supplies authenticated requests, bounded pagination, and distribution checks.

- `check-inline-ui-browser.js` is an expression to evaluate in a loopback WildBots preview. It checks the real sandbox's DOM, cookie, storage and fetch isolation, then attempts a navigation. Browser diagnostics must show `frame-src about:` blocking that navigation with no outbound request.
- `PREVIEW_INLINE_UI=1 node .agents/tools/preview-app.mjs` shows a local hay supply calculator for inline rendering, resizing, theme, keyboard and reset checks. It uses synthetic data.

- `python3 .agents/tools/stage-recovery-tools.py MERGED_COMMIT --host SSH_ALIAS --app-base PATH` copies the exact Git recovery helper and its `deploy_common.py` into a fresh private host audit directory, verifies their hashes and records provenance without changing live services or app source.
- `python3 .agents/tools/setup-shared-computer.py` stages private desktop/browser and terminal settings on the Hermes Linux service account without restarting live services; `--start` enables the shared computer after guarded release activation.
- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/accept-shared-computer.mjs PRIVATE_RECEIPT_PATH` checks authenticated native RFB, takeover/handback and a real terminal reconnect/end through the deployed app on its Linux host; uses a terminal administrator with a pre-confirmed temporary app session, so administrators get one "System terminal opened" alert; refuses to touch an existing member shell and removes its temporary app session.
- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/accept-household-experience.mjs PRIVATE_RECEIPT_PATH` runs with the deployed release as its working directory to check authenticated Today, native profile memory, vault metadata, schedule previews and synthetic speech through loopback services; refuses maintenance, verifies conversations stay unchanged, and removes its temporary app session. The helper may be uploaded outside the release and invoked by absolute path.

- `python3 .agents/tools/source-state.py` prints the source fingerprint used by the validation ledger, excluding the ledger (`docs/ledger/` and the archive `docs/ValidationLedger.md`) and ignored build/runtime files; optional path-prefix arguments restrict the fingerprint to a component.
- `python3 .agents/tools/review-collage.py output.png 'Label=screenshot.png' ...` combines screenshots at a common height with labels sized for that height and preserved aspect ratios; requires Pillow 10.1 or newer. Use short labels that fit each panel.
- `python3 .agents/tools/archive-spike-evidence.py SOURCE_DIRECTORY DESTINATION_DIRECTORY` archives successful disposable qualification receipts with a content manifest and refuses to replace historical evidence or publish raw home paths. `--isolated-host-home ABSOLUTE_PATH` redacts the disposable staged HOME before hashing public receipts.
- `python3 .agents/tools/archive-app-qualification.py NAME DESTINATION_DIRECTORY` fetches a completed release qualification into ignored private storage, checks its marked stage ownership and archives sanitized receipts with the existing evidence tool.
- `python3 .agents/tools/deploy-app-release.py --config PRIVATE_ABSOLUTE_JSON` bootstraps upgrade guards with a built release using native retirement/drain, verifies Google and guarded gateway recovery, and retains private rollback copies.
- `.agents/tools/deploy_common.py` holds the host steps the bootstrap, guarded and recovery tools share: commands under the held update claim, user systemd, atomic writes, readiness, Google and gateway checks. Each tool imports it from its own directory and passes an explicit `Deployment` context. Native calls set `HERMES_HOME` to the configured `hermesHome` before Hermes bootstrap can latch the process identity. The tools never write bytecode into a release. Every release tool guards with its `fence(condition, why)` instead of `assert`, so `python -O` cannot strip a guard, and a failed cutover prints `Stopped at fence: why` with its needs-review line. Host programs sent as source keep `assert` but refuse to start under `-O` or `PYTHONOPTIMIZE`.
- `.agents/tools/host_access.py` holds the `ssh` and `scp` calls the local release tools make to the Hermes host: `BatchMode`, `ConnectTimeout` and `ServerAlive` options so an unattended loop never waits on a password or host-key prompt or a dropped connection, plus a timeout each call site must choose. Import it from beside the tool. Programs sent to the host stay as source in the tools.
- `python3 .agents/tools/deploy-guarded-app-release.py --config PRIVATE_ABSOLUTE_JSON` activates subsequent built releases while holding the worker and native updater locks, proves fresh idle admission, and verifies original Google and Discord connections before reopening work. `newQualificationReceipt` supplies a freshly verified record, activated with the release after services stop; the previous record is retained for recovery.
- `python3 .agents/tools/recover-app-after-native-update.py --config PRIVATE_ABSOLUTE_JSON` restores the current app's qualification after an external native update disabled its private hooks; requires a fresh full receipt for that unchanged app, native Google retirement and a drain bound to the old gateway generation. It preserves the release and existing guards, restarts only app/dashboard/gateway under an owned lease, and refuses uncertain replay. Its checked configuration pins the SHA256 of the `deploy_common.py` beside it as `deployFunctionsSha256`; `release-app.py recover` pins whichever shared file the live helper names, so a release from before the module still pins `deploy-app-release.py`. `--check` validates the same config before execution. After inspecting a failure before receipt installation, `--resume-stopped` can continue the same operation once, only with all old services stopped, its owned drain and unchanged receipt intact. `--finish-guarded` verifies and opens an inspected, already restarted operation once under its original lease, without restarting services or rewriting the receipt.
- `python3 .agents/tools/qualify-app-release.py NAME` runs the full native integration and private authentication regressions for an unactivated staged release in disposable homes and a separate PM generation. It verifies source, repair, archive and input hashes before issuing an owner-private receipt for `release-app.py prepare --qualification`. On hosts where PM Chromium cannot use the OS sandbox, `--computer-probe-browser /opt/google/chrome/chrome` selects an existing sandboxed browser only for the local-network probe. Supply the direct host ELF executable, not a launcher script. Its requested path, resolved executable and hash are checked before and after qualification and saved as optional `computerProbeBrowser` metadata in the private receipt. Controlled activation carries that selection into later in-app update checks. Each new check binds a fresh hash at the same canonical path; missing, malformed or retargeted selections fail closed. Other probes retain pinned PM Chromium. Receipts without this metadata keep the default browser. Each run then removes its roughly 3 GB disposable checkout and runtime, keeping receipts, logs and probe evidence, and prunes earlier stages interrupted more than a day ago.
- `python3 .agents/tools/probe-computer-native.py --python QUALIFIED_DISPOSABLE_INTERPRETER` exercises native shared-computer tool, lease and recovery contracts in a new owner-private disposable VPS home.
- `scripts/spike/computer_local_network_probe.py` rehearses profile-scoped local-network admission against real native Hermes modules and disposable Chrome, including provenance, terminal policy, leases and invalid TLS; see `docs/SharedComputer.md` for the isolated runtime environment.
- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/hermes-update.mjs status|check|install CANDIDATE_REVISION|control retry|cancel|restart_service` runs with the deployed release as its working directory and drives the app's own Hermes updater as the designated update administrator, so admission, busy-assistant and recovery rules still apply. Each call uses a two-minute, pre-confirmed app session that it deletes, and prints the updater status. Add `--wait` to follow the operation through the app's status, which alone notices a worker that died mid-operation: it prints each phase change and exits 0 on ready or succeeded, 1 on any other settled phase, 2 at once when the app reports the worker interrupted, and 3 after four hours still running. Never poll raw `shared/upgrade-state/status.json` instead. The helper may be uploaded outside the release and invoked by absolute path.
- `python3 .agents/tools/merge-ledger-main.py [--push]` merges `origin/main` into the checked-out `docs/` branch. Only for docs branches opened before entries moved to one file each under `docs/ledger/`: they added their entry at the top of the frozen archive `docs/ValidationLedger.md`, so stacked ones conflict there. It resolves that conflict as main's archive (header included) with the branch's own entries, any whose text main lacks, on top, verbatim, and aborts on any other conflict. Remove it once no such branch is open.
- `python3 .agents/tools/prepare-when-idle.py COMMIT --host SSH_ALIAS --app-base PATH [--qualification RECEIPT]` reruns `release-app.py prepare` every two minutes while the guarded preflight refuses because assistants are busy, discarding each refused stage; any other failure stops it at once. Each busy attempt prints what the gateway reports, and agents counted with no listed work for 20 minutes or more get a one-time stuck-turn hint (see `docs/Hosting.md`). Gives up after 40 minutes by default.
- `python3 .agents/tools/release-app.py prepare COMMIT --host SSH_ALIAS --app-base PATH` builds a merged commit locally and on the host, requires matching web builds, derives the guarded deploy configuration from the last successful release and live state, and runs the no-change preflight. It refuses changed integration inputs without `--qualification` and a changed upgrade helper without `--accept-helper-change`. `activate NAME` runs the guarded activation, verifies the public build, services and maintenance, then writes the production receipt and a ledger entry file under `docs/ledger/` and opens their docs PR. The PR branch `docs/record-NAME` starts from the latest `origin/main` in a temporary worktree under the checkout's ignored `.private/docs-pr-worktrees`, so the operator's checkout is untouched; the tool prints the PR URL and never merges it. `--no-docs-pr` skips the PR. After activation it removes old release builds, keeping the ten newest plus the live release and its rollback target. A failed git or gh step only warns with the manual commands: the release stays recorded, and `record NAME` retries without a second ledger entry or PR. Both are keyed by the release, so a second release of the same commit gets its own entry and PR. `verify NAME` repeats the read-only checks; `discard NAME` removes an unactivated release, but refuses one holding a qualification receipt unless given `--include-qualification`. After an outside `hermes update` disables the add-on, prepare the live commit, qualify it, then `recover NAME` builds the recovery configuration from the live release and runs `recover-app-after-native-update.py` right after a fresh gateway heartbeat: `--check` alone, otherwise the check and then the recovery. Manifests stay in ignored `.private/releases`.
- `node .agents/tools/native-smoke.mjs http://127.0.0.1:3004` verifies one-time native authentication, a canonical Hermes conversation, Origin rejection and revocation against a running loopback server with explicit local test accounts. It never prints credentials.
- `bash .agents/tools/validate-ios.sh SIMULATOR_UUID [test|build|live]` runs the native app's simulator checks on the Mac mini with local ad hoc signing for Keychain, task-local derived data and a unique result bundle. It holds the shared `.private/ios-validation.lock` of the main checkout itself and exits at once if another run holds it, so never wrap it in `lockf`. It refuses to boot a fourth simulator and shuts down a simulator it booted. `test` and `live` build once with `build-for-testing`, then run `test-without-building` from a copy of the `.xctestrun` that `patch-xctestrun.py` gives a 15-second crash-report wait, and skip the failure-time `simctl diagnose` unless given `-collect-test-diagnostics on-failure`. Each test run writes `.private/ios-<run>.txt` with the commit, the iOS input fingerprint, Xcode, simulator, the operation, project, scheme, destination, derived data, the effective build and test options and the test summary, so a later run of identical inputs and options can reuse the result. Choose a simulator reserved for this work, and set `IOS_DERIVED_DATA` to a separate path for each concurrent build. `live` explicitly exercises the real loopback app server at port 3004; prepare its isolated Hermes fixture first. Additional xcodebuild options follow the operation: test selection, repetition and parallelism options, such as `-only-testing`, `-test-iterations` and `-parallel-testing-worker-count`, go to the test run, and the rest to the build.
- `python3 .agents/tools/patch-xctestrun.py SOURCE DESTINATION SECONDS` copies an `.xctestrun` beside the original with `XCTCrashReportCollectionTimeout` set for every UI test target, as a launch argument and in the environment. Without it the Mac mini waits about 300 seconds after every UI test.

- `python3 .agents/tools/archive-release.py OUTPUT.tar.gz` packages Git-visible server, build and test inputs without ignored credentials, runtime data or macOS extended-attribute files.

- `node .agents/tools/preview-app.mjs` serves the built web client on loopback port 3000 with explicit household, conversation, avatar-state, model catalog, artifact files, account/status and update-recovery fixtures. Attachment uploads take four seconds so progress is visible, and a file name containing `fail` exercises Retry. Kitchen companion has a 64-turn history for paging earlier messages, Kitchen companion and Trail guide show as unread on home, and `PREVIEW_ARRIVALS=1` adds a kitchen reply every eight seconds for the new-message control, announced on the conversation change stream as the app server does. `PREVIEW_CLIENT_DIR` serves a saved client build for before/after comparisons, and `PREVIEW_PORT` selects a separate loopback port. `PREVIEW_THEME` and `PREVIEW_PRESENTATION` set the initial preferences; `PREVIEW_HOST` can select a trusted LAN address when the collaborative browser runs on another machine. `PREVIEW_COORDINATION=1` shows synthetic scheduled answers with bot, subagent, process and diagnostic activity for disclosure review. `PREVIEW_SECURE_REQUEST=login|code|unlock|secret` adds a synthetic inline credential request; `PREVIEW_SECURE_FAILURE=1` exercises uncertain settlement without storing secrets. `PREVIEW_SIGNED_OUT=1` and `PREVIEW_DISCONNECTED=1` exercise entry/recovery pages; `PREVIEW_PUSH_CONFIGURED=1 PREVIEW_NOTIFICATION_PROMPT=1` shows the notification invitation on an insecure LAN for visual review only, with push still unsupported. Creating an assistant adds it to the fixture, and `PREVIEW_AVATAR_FAILURE=1` fails its first avatar save so the retry path can be checked. Hermes revisions carry commit dates. `PREVIEW_TERMINAL=confirm|restricted` shows the terminal's sign-in confirmation or non-administrator state. It serves the app's real Content-Security-Policy and prints any violation report to stderr. It never contacts Hermes or account providers, except that `PREVIEW_GOOGLE_CLIENT_ID` loads Google's real sign-in button.
