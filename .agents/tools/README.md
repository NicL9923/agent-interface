# Repository tools


- `check-home-touch.js` is a Playwright CLI run-code function that uses real Chromium touch input to long-press an assistant, checks that the menu backdrop intercepts outside taps, and confirms dismissal keeps home open.

- `capture-design.js` is a Playwright CLI run-code function that captures Today, assistants home, conversation, questions, approvals, failed/interrupted turns, assistant details and artifacts, assistant creation/settings, the Avatar editor, models/tools/skills, or profile Memory at desktop, tablet and phone widths. Pass `{ outputDir, prefix, screen, fixture }` with a matching `.agents/fixtures/*-design.json` to use the same populated data as the native design tour. It covers dark and large text, screen-specific empty and failure states, viewport overflow, conversation draft, clipboard and keyboard focus, and question answers or approval decisions with failure and retry. Recovery captures check draft preservation, refused and unconfirmed retries, request ID reuse and the interruption review gate.
- `npm exec tsx .agents/tools/check-memory-fixture.ts` verifies every Memory design fixture state against the production schema, digest rules and declared synthetic character-count delimiter.
- `python3 .agents/tools/capture-design.py SCREEN before|after --root ARTIFACT_DIRECTORY --origin LOOPBACK_ORIGIN --session OWNED_SESSION` runs `capture-design.js` with the matching shared fixture and saves its screenshots and JSON report. Use `--report NAME` to retain separate revision reports. It rejects incomplete conversation fixtures before browser launch, uses the installed CLI or pinned 0.1.22, and preserves the last good report if a run fails. Failed browser runs retain a diagnostic screenshot and page-error messages. Put the CLI that opened the session on PATH when reusing an npx-cached installation. Use `work after --work-case clear-confirmation` for the single-frame Clear spacing recheck. It verifies focus before the screenshot helper blurs it and requires zero writes. Use `work before --work-case tasks` for the full W2 BEFORE set. Use `work after --work-case tasks --task-gate a` for the W2a-only AFTER set, with the `work-tasks-a-after` report and its own screenshot directory. Use `work after --work-case tasks --task-gate b` for the separate 16-frame W2b task-editor tour. Each gate requires its own new `--report work-tasks-a-...` or `work-tasks-b-...` basename and refuses existing output. Combined W2 AFTER capture is not supported.
- `python3 .agents/tools/annotate-design.py SPEC.json OUTPUT.png` combines before/after screenshots with numbered pointers and matching notes. Requires Pillow. The specification has a `title` and `before`/`after` objects with `image` and `notes`, each note supplying `point` in pixels or `fraction` of image width/height, `text`, and an optional `offset`. `--batch MANIFEST.json` regenerates only listed comparisons, with relative `spec` and `output` paths under the manifest directory.

- `python3 .agents/tools/benchmark-open-during-turn.py [--repo CHECKOUT] [--rows 5000] [--opens 30] [--plan] [--contend]` times `agent-interface.open` on a long synthetic transcript while a turn runs, with the Python test fakes and a temp SQLite store carrying Hermes's exact `messages` table and indexes in WAL mode. A tool row is committed before each open, as in a running turn, and the compaction-copy lookup `original_rows` is timed on its own; pass an export of another commit as `--repo` to compare its add-on, `--plan` to print the query plan of each statement the add-on ran, and `--contend` to time the journal lock: the open's holds, its attribution pass, and the wait of a frame thread recording live tool calls beside it. Fake native projection, so it measures the add-on's own work, not Hermes's. The machine's load moves single runs by 2x; compare interleaved repeats.
- `node .agents/tools/measure-first-load.mjs [--runs 7] [--theme dark] [--only cold,warm,worker] [--compare A=DIR,B=DIR --rounds 3] [--seed N] [--browser-cores 0-7 --server-cores 8-11] [--max-load N] [--allow-busy] [--json OUT]` measures, in Chromium against the real app server (`e2e/server.ts`, port 4173) with Slow 4G and a 4x CPU slowdown, when bootstrap is sent and answered, first paint, when the chosen theme lands and when the roster paints, from the page's own Performance API marks, with no worker and a cold or warm HTTP cache and under the worker's cached shell. Each figure is a median with its quartiles and count. `--compare` serves saved copies of `dist/client` in a freshly shuffled order every round, restores the current one, and reports each build's difference from the first with a 95% bootstrap interval. The browser and server are pinned to their own cores, and the load average is recorded; above a quarter of the logical cores the comparison is not printed as a result without `--allow-busy`. Run `npm run build` first.

- `sudo python3 .agents/tools/metadata-egress-floor.py install --user SERVICE_USER|check [--user SERVICE_USER] [--egress HOST:PORT]|remove` runs on the Hermes host. It installs the nftables table `inet agent_interface_metadata`, which rejects the service account's connections to `169.254.169.254` and `fe80::a9fe:a9fe`, without flushing the ruleset or touching ufw. It adds a marked include at the end of `/etc/nftables.conf` so nftables reloads keep it, an `nftables.service` drop-in whose `ExecStop=` flushes and reloads the floor in one transaction, a boot unit the service account's `user@UID.service` requires, which fails closed, and a read-only sudo rule for `nft -j list table`. Install is idempotent, never restarts a unit, and refuses uid 0. `check` reports the persistence mode, compares the live rules, and proves as the service user that metadata is explicitly refused on IPv4 and each link-local IPv6 interface while DNS and HTTPS egress work. See `docs/Hosting.md`.

- `.agents/tools/deploy_common.py` holds the host steps the bootstrap, guarded and recovery tools share: commands under the held update claim, user systemd, atomic writes, readiness, Google and gateway checks. Each tool imports it from its own directory and passes an explicit `Deployment` context. Native calls set `HERMES_HOME` to the configured `hermesHome` before Hermes bootstrap can latch the process identity. The tools never write bytecode into a release. Every release tool guards with its `fence(condition, why)` instead of `assert`, so `python -O` cannot strip a guard, and a failed cutover prints `Stopped at fence: why` with its needs-review line. - `python3 .agents/tools/deploy-guarded-app-release.py --config PRIVATE_ABSOLUTE_JSON` activates subsequent built releases while holding the worker and native updater locks, proves fresh idle admission, and verifies original Google and Discord connections before reopening work. It writes the blocked update status, takes Hermes's maintenance lease while the app still runs, and only then stops the app. When Hermes answers that work is still busy, it releases the lease, restores the saved status and exits 75 with nothing stopped. An acquire with no answer within 120 s, whose lease can still appear, and any other failure exit 2 with the blocked status kept and hold the operation for review; docs/HermesUpgradeLinux.md says how to clear an unanswered acquire. `newQualificationReceipt` supplies a freshly verified record, activated with the release after services stop; the previous record is retained for recovery. After the switch it links `<HERMES_HOME>/plugins/wildbots-voice` through `current` once, and refuses before stopping services if another folder or link holds that path; enabling the plugin stays manual (see docs/Hosting.md).
- `python3 .agents/tools/recover-app-after-native-update.py --config PRIVATE_ABSOLUTE_JSON` restores the current app's qualification after an external native update disabled its private hooks; requires a fresh full receipt for that unchanged app, native Google retirement and a drain bound to the old gateway generation. It preserves the release and existing guards, restarts only app/dashboard/gateway under an owned lease, and refuses uncertain replay. Its checked configuration pins the SHA256 of the `deploy_common.py` beside it as `deployFunctionsSha256`; `release-app.py recover` pins whichever shared file the live helper names, so a release from before the module still pins `deploy-app-release.py`. `--check` validates the same config before execution. After inspecting a failure before receipt installation, `--resume-stopped` can continue the same operation once, only with all old services stopped, its owned drain and unchanged receipt intact. `--finish-guarded` verifies and opens an inspected, already restarted operation once under its original lease, without restarting services or rewriting the receipt.
- `python3 .agents/tools/qualify-app-release.py NAME` runs the full native integration and private authentication regressions for an unactivated staged release in disposable homes and a separate PM generation. It verifies source, repair, archive and input hashes before issuing an owner-private receipt for `release-app.py prepare --qualification`. On hosts where PM Chromium cannot use the OS sandbox, `--computer-probe-browser /opt/google/chrome/chrome` selects an existing sandboxed browser only for the local-network probe. Without either browser flag, it reuses the live qualification receipt's selection and binds it afresh, so a host that needed one keeps it. The receipt must be the runtime's own owner-only file, not a link, and a requested path that now resolves to another executable is refused; `--pinned-probe-browser` runs the release's PM Chromium instead, and malformed live metadata refuses before staging. Supply the direct host ELF executable, not a launcher script. Its requested path, resolved executable and hash are checked before and after qualification and saved as optional `computerProbeBrowser` metadata in the private receipt. Controlled activation carries that selection into later in-app update checks. Each new check binds a fresh hash at the same canonical path; missing, malformed or retargeted selections fail closed. Other probes retain pinned PM Chromium. Receipts without this metadata keep the default browser. Each run then removes its roughly 3 GB disposable checkout and runtime, keeping receipts, logs and probe evidence, and prunes earlier stages interrupted more than a day ago.

- `.agents/tools/check-all [--only LIST] [--skip LIST] [--py auto|always|never] [--keep-going] [--verbose] [--heavy-slots N]` runs typecheck, lint, ruff, test, build, e2e and py in that order, stops at the first failure unless `--keep-going`, and prints one table with each check's result, queue time, run time and the counts its tool reported. Run it before calling work done; its output replaces running the seven commands by hand. `--py auto` runs the Python suite when the diff against `origin/main` (`--base`) touches Python or a file the Python tests read (`src/hermes/`, `scripts/`, `.agents/tools/`, `src/shared/`, `public/voice-previews/`); ruff always runs. It refuses to start, with the fix, when `node_modules` is missing or older than `package-lock.json` (`npm ci`), when node is outside `package.json`'s range, or when ruff 0.17.3 (the pin in `.github/requirements-ci.txt`) is neither on PATH nor installable; it warns when `node_modules` is a symlink. It picks a free app and control port pair for the browser suite (a pair of ports from 24100 up, held under a lock until the suite ends, and your own `E2E_PORT` is used if you set one), and at most `--heavy-slots` (or `CHECK_ALL_HEAVY_SLOTS`, default 1) of test, e2e and py run on the machine at once across all worktrees; others queue, up to `--lock-timeout` seconds (exit 75). Locks are `flock` files under `$CHECK_ALL_HOME` (default `~/.cache/agent-interface/check-all`, or `~/Library/Caches/agent-interface/check-all` on macOS). Each check's processes inherit them, so they free when the last of those processes ends: a `check-all` killed with SIGKILL leaves its suite running and its slot taken until the suite finishes. Ctrl-C, SIGTERM and `--check-timeout` send the check SIGINT, wait up to 10 seconds for it to shut down (Playwright stops its own web server then), and kill what is left, freeing the locks only after. The cached ruff venv and the last 30 runs' logs live there too. Exit codes: 0 passed, 1 a check failed, 2 refused to run, 75 gave up queueing, 130 interrupted. Logic in `check_all.py`, tests in `tests/check_all_test.py`.
