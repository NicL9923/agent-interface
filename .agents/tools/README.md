# Repository tools

- `python3 .agents/tools/stage-recovery-tools.py MERGED_COMMIT --host SSH_ALIAS --app-base PATH` copies exact Git recovery helpers into a fresh private host audit directory, verifies their hashes and records provenance without changing live services or app source.
- `python3 .agents/tools/setup-shared-computer.py` stages private desktop/browser and terminal settings on the Hermes Linux service account without restarting live services; `--start` enables the shared computer after guarded release activation.
- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/accept-shared-computer.mjs PRIVATE_RECEIPT_PATH` checks authenticated native RFB, takeover/handback and a real terminal reconnect/end through the deployed app on its Linux host; uses a terminal administrator with a pre-confirmed temporary app session, so administrators get one "System terminal opened" alert; refuses to touch an existing member shell and removes its temporary app session.
- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/accept-household-experience.mjs PRIVATE_RECEIPT_PATH` runs with the deployed release as its working directory to check authenticated Today, native profile memory, vault metadata, schedule previews and synthetic speech through loopback services; refuses maintenance, verifies conversations stay unchanged, and removes its temporary app session. The helper may be uploaded outside the release and invoked by absolute path.

- `python3 .agents/tools/source-state.py` prints the source fingerprint used by the validation ledger, excluding the ledger itself and ignored build/runtime files; optional path-prefix arguments restrict the fingerprint to a component.
- `python3 .agents/tools/review-collage.py output.png 'Label=screenshot.png' ...` combines screenshots at a common height with labels and preserved aspect ratios; requires Pillow.
- `python3 .agents/tools/archive-spike-evidence.py SOURCE_DIRECTORY DESTINATION_DIRECTORY` archives successful disposable qualification receipts with a content manifest and refuses to replace historical evidence or publish raw home paths. `--isolated-host-home ABSOLUTE_PATH` redacts the disposable staged HOME before hashing public receipts.
- `python3 .agents/tools/archive-app-qualification.py NAME DESTINATION_DIRECTORY` fetches a completed release qualification into ignored private storage, checks its marked stage ownership and archives sanitized receipts with the existing evidence tool.
- `python3 .agents/tools/deploy-app-release.py --config PRIVATE_ABSOLUTE_JSON` bootstraps upgrade guards with a built release using native retirement/drain, verifies Google and guarded gateway recovery, and retains private rollback copies.
- `python3 .agents/tools/deploy-guarded-app-release.py --config PRIVATE_ABSOLUTE_JSON` activates subsequent built releases while holding the worker and native updater locks, proves fresh idle admission, and verifies original Google and Discord connections before reopening work. `newQualificationReceipt` supplies a freshly verified record, activated with the release after services stop; the previous record is retained for recovery.
- `python3 .agents/tools/recover-app-after-native-update.py --config PRIVATE_ABSOLUTE_JSON` restores the current app's qualification after an external native update disabled its private hooks; requires a fresh full receipt for that unchanged app, native Google retirement and a drain bound to the old gateway generation. It preserves the release and existing guards, restarts only app/dashboard/gateway under an owned lease, and refuses uncertain replay. `--check` validates the same config before execution. After inspecting a failure before receipt installation, `--resume-stopped` can continue the same operation once, only with all old services stopped, its owned drain and unchanged receipt intact. `--finish-guarded` verifies and opens an inspected, already restarted operation once under its original lease, without restarting services or rewriting the receipt.
- `python3 .agents/tools/qualify-app-release.py NAME` runs the full native integration and private authentication regressions for an unactivated staged release in disposable homes and a separate PM generation. It verifies source, repair, archive and input hashes before issuing an owner-private receipt for `release-app.py prepare --qualification`. Each run then removes its roughly 3 GB disposable checkout and runtime, keeping receipts, logs and probe evidence, and prunes earlier stages interrupted more than a day ago.
- `python3 .agents/tools/probe-computer-native.py --python QUALIFIED_DISPOSABLE_INTERPRETER` exercises native shared-computer tool, lease and recovery contracts in a new owner-private disposable VPS home.
- `python3 .agents/tools/prepare-when-idle.py COMMIT --host SSH_ALIAS --app-base PATH [--qualification RECEIPT]` reruns `release-app.py prepare` every two minutes while the guarded preflight refuses because assistants are busy, discarding each refused stage; any other failure stops it at once. Gives up after 40 minutes by default.
- `python3 .agents/tools/release-app.py prepare COMMIT --host SSH_ALIAS --app-base PATH` builds a merged commit locally and on the host, requires matching web builds, derives the guarded deploy configuration from the last successful release and live state, and runs the no-change preflight. It refuses changed integration inputs without `--qualification` and a changed upgrade helper without `--accept-helper-change`. `activate NAME` runs the guarded activation, verifies the public build, services and maintenance, then writes the production receipt and ledger entry for a docs PR. `verify NAME` repeats the read-only checks; `discard NAME` removes an unactivated release. After an outside `hermes update` disables the add-on, prepare the live commit, qualify it, then `recover NAME` builds the recovery configuration from the live release and runs `recover-app-after-native-update.py` right after a fresh gateway heartbeat: `--check` alone, otherwise the check and then the recovery. Manifests stay in ignored `.private/releases`.
- `node .agents/tools/native-smoke.mjs http://127.0.0.1:3004` verifies one-time native authentication, a canonical Hermes conversation, Origin rejection and revocation against a running loopback server with explicit local test accounts. It never prints credentials.
- `bash .agents/tools/validate-ios.sh SIMULATOR_UUID [test|build|live]` runs the native app's simulator checks on the Mac mini with local ad hoc signing for Keychain, task-local derived data and a unique result bundle. Choose a simulator reserved for this work. `live` explicitly exercises the real loopback app server at port 3004; prepare its isolated Hermes fixture first.
- `bash .agents/tools/ios-screenshot-tour.sh SIMULATOR_UUID OUTPUT_DIR` writes numbered PNGs of the Debug fixture tour (home, conversation, avatar editor, preferences, integrations, Hermes updates, avatar specimen, dark theme) for visual before/after review.
- `node .agents/tools/backup-app.mjs APP_DATABASE BACKUP_DIRECTORY` makes a private online SQLite backup, checks its integrity, and retains the latest 14 completed copies. It removes its temporary copy with its `-shm`/`-wal` files, and stale partial copies over an hour old. It includes committed WAL data and does not back up Hermes or host secrets. Point the app's `APP_BACKUP_DIR` at the same directory for the readiness check.
- `python3 .agents/tools/archive-release.py OUTPUT.tar.gz` packages Git-visible server, build and test inputs without ignored credentials, runtime data or macOS extended-attribute files.

- `node .agents/tools/preview-app.mjs` serves the built web client on loopback port 3000 with explicit household, conversation, avatar-state, model catalog, artifact files, account/status and update-recovery fixtures. `PREVIEW_THEME` and `PREVIEW_PRESENTATION` set the initial preferences; `PREVIEW_HOST` can select a trusted LAN address when the collaborative browser runs on another machine. `PREVIEW_SECURE_REQUEST=login|code|unlock|secret` adds a synthetic inline credential request; `PREVIEW_SECURE_FAILURE=1` exercises uncertain settlement without storing secrets. `PREVIEW_SIGNED_OUT=1` and `PREVIEW_DISCONNECTED=1` exercise entry/recovery pages; `PREVIEW_PUSH_CONFIGURED=1 PREVIEW_NOTIFICATION_PROMPT=1` shows the notification invitation on an insecure LAN for visual review only, with push still unsupported. `PREVIEW_TERMINAL=confirm|restricted` shows the terminal's sign-in confirmation or non-administrator state. It serves the app's real Content-Security-Policy and prints any violation report to stderr. It never contacts Hermes or account providers, except that `PREVIEW_GOOGLE_CLIENT_ID` loads Google's real sign-in button.
