# Repository tools


- `check-home-touch.js` is a Playwright CLI run-code function that uses real Chromium touch input to long-press an assistant, checks that the menu backdrop intercepts outside taps, and confirms dismissal keeps home open.

- `capture-design.js` is a Playwright CLI run-code function that captures Today, assistants home, conversation, questions, approvals, failed/interrupted turns, assistant details and artifacts, assistant creation/settings, the Avatar editor, models/tools/skills, or profile Memory at desktop, tablet and phone widths. Pass `{ outputDir, prefix, screen, fixture }` with a matching `.agents/fixtures/*-design.json` to use the same populated data as the native design tour. It covers dark and large text, screen-specific empty and failure states, viewport overflow, conversation draft, clipboard and keyboard focus, and question answers or approval decisions with failure and retry. Recovery captures check draft preservation, refused and unconfirmed retries, request ID reuse and the interruption review gate.
- `npm exec tsx .agents/tools/check-memory-fixture.ts` verifies every Memory design fixture state against the production schema, digest rules and declared synthetic character-count delimiter.
- `python3 .agents/tools/capture-design.py SCREEN before|after --root ARTIFACT_DIRECTORY --origin LOOPBACK_ORIGIN --session OWNED_SESSION` runs `capture-design.js` with the matching shared fixture and saves its screenshots and JSON report. Use `--report NAME` to retain separate revision reports. It rejects incomplete conversation fixtures before browser launch, uses the installed CLI or pinned 0.1.22, and preserves the last good report if a run fails. Failed browser runs retain a diagnostic screenshot and page-error messages. Put the CLI that opened the session on PATH when reusing an npx-cached installation. Use `work after --work-case clear-confirmation` for the single-frame Clear spacing recheck. It verifies focus before the screenshot helper blurs it and requires zero writes. Use `work before --work-case tasks` for the full W2 BEFORE set. Use `work after --work-case tasks --task-gate a` for the W2a-only AFTER set, with the `work-tasks-a-after` report and its own screenshot directory. Use `work after --work-case tasks --task-gate b` for the separate 16-frame W2b task-editor tour. Each gate requires its own new `--report work-tasks-a-...` or `work-tasks-b-...` basename and refuses existing output. Combined W2 AFTER capture is not supported.
- `python3 .agents/tools/annotate-design.py SPEC.json OUTPUT.png` combines before/after screenshots with numbered pointers and matching notes. Requires Pillow. The specification has a `title` and `before`/`after` objects with `image` and `notes`, each note supplying `point` in pixels or `fraction` of image width/height, `text`, and an optional `offset`. `--batch MANIFEST.json` regenerates only listed comparisons, with relative `spec` and `output` paths under the manifest directory.

- `sudo python3 .agents/tools/metadata-egress-floor.py install --user SERVICE_USER|check [--user SERVICE_USER] [--egress HOST:PORT]|remove` runs on the Hermes host. It installs the nftables table `inet agent_interface_metadata`, which rejects the service account's connections to `169.254.169.254` and `fe80::a9fe:a9fe`, without flushing the ruleset or touching ufw. It adds a marked include at the end of `/etc/nftables.conf` so nftables reloads keep it, an `nftables.service` drop-in whose `ExecStop=` flushes and reloads the floor in one transaction, a boot unit the service account's `user@UID.service` requires, which fails closed, and a read-only sudo rule for `nft -j list table`. Install is idempotent, never restarts a unit, and refuses uid 0. `check` reports the persistence mode, compares the live rules, and proves as the service user that metadata is explicitly refused on IPv4 and each link-local IPv6 interface while DNS and HTTPS egress work. See `docs/Hosting.md`.

- `.agents/tools/deploy_common.py` holds the host steps the bootstrap, guarded and recovery tools share: commands under the held update claim, user systemd, atomic writes, readiness, Google and gateway checks. Each tool imports it from its own directory and passes an explicit `Deployment` context. Native calls set `HERMES_HOME` to the configured `hermesHome` before Hermes bootstrap can latch the process identity. The tools never write bytecode into a release. Every release tool guards with its `fence(condition, why)` instead of `assert`, so `python -O` cannot strip a guard, and a failed cutover prints `Stopped at fence: why` with its needs-review line. Host programs sent as source keep `assert` but refuse to start under `-O` or `PYTHONOPTIMIZE`.
- `.agents/tools/host_access.py` holds the `ssh` and `scp` calls the local release tools make to the Hermes host: `BatchMode`, `ConnectTimeout` and `ServerAlive` options so an unattended loop never waits on a password or host-key prompt or a dropped connection, plus a timeout each call site must choose. Import it from beside the tool. Programs sent to the host stay as source in the tools.
- `python3 .agents/tools/deploy-guarded-app-release.py --config PRIVATE_ABSOLUTE_JSON` activates subsequent built releases while holding the worker and native updater locks, proves fresh idle admission, and verifies original Google and Discord connections before reopening work. `newQualificationReceipt` supplies a freshly verified record, activated with the release after services stop; the previous record is retained for recovery. After the switch it links `<HERMES_HOME>/plugins/wildbots-voice` through `current` once, and refuses before stopping services if another folder or link holds that path; enabling the plugin stays manual (see docs/Hosting.md).
- `python3 .agents/tools/recover-app-after-native-update.py --config PRIVATE_ABSOLUTE_JSON` restores the current app's qualification after an external native update disabled its private hooks; requires a fresh full receipt for that unchanged app, native Google retirement and a drain bound to the old gateway generation. It preserves the release and existing guards, restarts only app/dashboard/gateway under an owned lease, and refuses uncertain replay. Its checked configuration pins the SHA256 of the `deploy_common.py` beside it as `deployFunctionsSha256`; `release-app.py recover` pins whichever shared file the live helper names, so a release from before the module still pins `deploy-app-release.py`. `--check` validates the same config before execution. After inspecting a failure before receipt installation, `--resume-stopped` can continue the same operation once, only with all old services stopped, its owned drain and unchanged receipt intact. `--finish-guarded` verifies and opens an inspected, already restarted operation once under its original lease, without restarting services or rewriting the receipt.
- `python3 .agents/tools/qualify-app-release.py NAME` runs the full native integration and private authentication regressions for an unactivated staged release in disposable homes and a separate PM generation. It verifies source, repair, archive and input hashes before issuing an owner-private receipt for `release-app.py prepare --qualification`. On hosts where PM Chromium cannot use the OS sandbox, `--computer-probe-browser /opt/google/chrome/chrome` selects an existing sandboxed browser only for the local-network probe. Supply the direct host ELF executable, not a launcher script. Its requested path, resolved executable and hash are checked before and after qualification and saved as optional `computerProbeBrowser` metadata in the private receipt. Controlled activation carries that selection into later in-app update checks. Each new check binds a fresh hash at the same canonical path; missing, malformed or retargeted selections fail closed. Other probes retain pinned PM Chromium. Receipts without this metadata keep the default browser. Each run then removes its roughly 3 GB disposable checkout and runtime, keeping receipts, logs and probe evidence, and prunes earlier stages interrupted more than a day ago.

- `node --env-file=PRIVATE_APP_ENV --import tsx .agents/tools/hermes-update.mjs status|check|install CANDIDATE_REVISION|control retry|cancel|restart_service` runs with the deployed release as its working directory and drives the app's own Hermes updater as the designated update administrator, so admission, busy-assistant and recovery rules still apply. Each call uses a two-minute, pre-confirmed app session that it deletes, and prints the updater status. Add `--wait` to follow the operation through the app's status, which alone notices a worker that died mid-operation: it ignores the previous operation's settled phase until the worker writes a newer status, prints each phase change and exits 0 on ready or succeeded, 1 on any other settled phase or when the requested operation has not started after five minutes, 2 at once when the app reports the worker interrupted, and 3 after four hours still running. Never poll raw `shared/upgrade-state/status.json` instead. The helper may be uploaded outside the release and invoked by absolute path.
- `python3 .agents/tools/merge-ledger-main.py [--push]` merges `origin/main` into the checked-out `docs/` branch. Only for docs branches opened before entries moved to one file each under `docs/ledger/`: they added their entry at the top of the frozen archive `docs/ValidationLedger.md`, so stacked ones conflict there. It resolves that conflict as main's archive (header included) with the branch's own entries, any whose text main lacks, on top, verbatim, and aborts on any other conflict. Remove it once no such branch is open.
- `python3 .agents/tools/prepare-when-idle.py COMMIT --host SSH_ALIAS --app-base PATH [PREPARE OPTIONS]` takes `release-app.py prepare`'s own argument definitions, so every prepare option, such as `--node`, `--qualification` and `--accept-helper-change`, is accepted and passed to each attempt. It reruns `release-app.py prepare` every two minutes while the guarded preflight refuses because assistants are busy, discarding each refused stage; any other failure stops it at once. Each busy attempt names the refusing check and what the gateway reports. A gateway count that persists for 5 minutes with no message written and no live routine run is reported as leaked; with `--household-idle` it restarts `hermes-gateway.service` once after an on-host re-check (see `docs/Hosting.md`). Gives up after 40 minutes by default.
- `python3 .agents/tools/renew-google-verification-session.py --host SSH_ALIAS --session-file HOST_PATH [--open]` renews the private Google verification session (`googleSessionFile`) that guarded releases and update checks use, when preflight reports "Original Google session verification failed". It prints a local start link; a household member signs in once, and it redeems Hermes's native PKCE code and replaces the host file under the same lock as `live-google-check.py`. Tokens are never printed.
- `python3 .agents/tools/release-app.py prepare COMMIT --host SSH_ALIAS --app-base PATH` builds a merged commit locally and on the host, requires matching web builds, derives the guarded deploy configuration from the last successful release and live state, and runs the no-change preflight. It refuses a host whose metadata egress floor is not enforcing live, judged with `metadata-egress-floor.py`'s own verdicts as the SSH (service) user, and it refuses changed integration inputs without `--qualification` and a changed upgrade helper without `--accept-helper-change`. It builds with the last release's Node unless `--node ABSOLUTE_PATH/node` names the app runtime the service now runs. It refuses a runtime outside `package.json`'s `engines`, and one the service's running process, its live `PATH`, `ExecStart` and configured `PATH` are not all on, or whose `EnvironmentFile` sets `PATH`. `activate` and `recover` check that again first. See docs/Hosting.md for changing it. The stage records the binary `--node` resolved to on the host, and `qualify-app-release.py`, the deploy and `recover` run that binary. `activate NAME` runs the guarded activation, verifies the public build, services and maintenance, then writes the production receipt and a ledger entry file under `docs/ledger/` and opens their docs PR. The PR branch `docs/record-NAME` starts from the latest `origin/main` in a temporary worktree under the checkout's ignored `.private/docs-pr-worktrees`, so the operator's checkout is untouched; the tool prints the PR URL and never merges it. `--no-docs-pr` skips the PR. After activation it removes old release builds, keeping the ten newest plus the live release and its rollback target. A failed git or gh step only warns with the manual commands: the release stays recorded, and `record NAME` retries without a second ledger entry or PR. Both are keyed by the release, so a second release of the same commit gets its own entry and PR. `verify NAME` repeats the read-only checks, including `metadataEgressFloor`; `discard NAME` removes an unactivated release, but refuses one holding a qualification receipt unless given `--include-qualification`. After an outside `hermes update` disables the add-on, prepare the live commit, qualify it, then `recover NAME` builds the recovery configuration from the live release and runs `recover-app-after-native-update.py` right after a fresh gateway heartbeat: `--check` alone, otherwise the check and then the recovery. Manifests stay in ignored `.private/releases`.

- `bash .agents/tools/validate-ios.sh SIMULATOR_UUID [test|build|live] [xcodebuild options...]` validates the native app under the shared Mac lock. Run it directly; verified nested calls also work. Requires the shared lock's `--check-held` support. Build-only work never boots a simulator. Test execution leaves pre-existing devices running and shuts down only its selected device if the device was shut down when test execution started. Tests default to serial execution, enabled Xcode test timeouts and no optional failure diagnostics. Explicit test-timeout settings are preserved.
