entry's change set. No Hermes process ran and nothing was deployed. Line numbers are this branch's. The change touches five files of

## Defect

`POST /bots/:id/stop` called `open(botId)` for the session ID and sent `session.interrupt` with no run (`src/server/hermes.ts`, formerly
lines 888 to 891). Read in the local upstream clone at `ed1afb0`: `session.interrupt` (`tui_gateway/methods_session_interrupt.py`) calls
`_interrupt_session_turn` (`tui_gateway/session_lifecycle.py:771`), which, whether or not a turn runs, clears `queued_prompt` and
`queued_prompts` (every member's) and bumps the queue generation, sets `_turn_cancel_requested`, interrupts a background memory or skill
review, and resolves every pending gateway approval with a deny (lines 793-797, 830-846). Only the hard interrupt of the agent and the
`running` reset need `running`. The cancel flag blocks notification turns and auto-continue until the next prompt. The interrupt takes
`expected_hosted_task_id` for a hosted room task only; a chat session has no run to name to Hermes.

So a Stop that reached an idle session, or one whose run had just finished and another member's next message was queued, lost that queue
and denied approvals. The Stop button and Cmd+. both act on what the screen showed some time before: Cmd+. asks first, and a Live Activity's
Stop can come minutes after its run ended.

## Change

- `src/server/hermes.ts:888-899` `stop(botId, runId?)`: reads the session (`open`), refuses with 409 `nothing_to_stop` when no run is open
  (`info.running` false and no `app_run_id`, the same test as the conversation read's `active`), refuses with 409 `run_changed` when `runId`
  is given and is not `app_run_id`, and only then sends the interrupt. A turn with no app run, such as one a Discord message started, has no
  run ID, so it matches no named run.
- `src/server/conversation-routes.ts:546-557`: the route reads `{ runId?, account? }` (strict; `runId` 1 to 200 characters; no body or `{}`
  allowed) and passes `runId` on. The account check still comes first.
- `src/shared/api.ts`: the route map now declares the body (`StopRequest | undefined`), so the web's call is typed. `src/shared/types.ts`:
  `Runtime.stop(botId, runId?)`. `src/shared/errors.ts`: the two codes and messages.
- Web: `useStopResponse` (`src/app/Composer.tsx:34`) sends `{ runId }` when it has one and `{}` otherwise. The Stop button names the run the
  screen shows as of the click (`src/App.tsx:432-433`). Cmd+. names the run as of the question it asked (`:434`, `:469`, `:616`), so a run
  that starts while the question is open is not stopped by the answer to a question about the earlier one.
- Docs: `docs/native-api.md` (Stop body and refusals), `docs/HermesCapabilityMatrix.md` (what `session.interrupt` does and what the app does).

## A client that names no run

iOS today sends `{}` from the chat (`ComposerView.swift:272`, `[String: String]()`) and `{ "account": ... }` from the Live Activity
(`LiveActivityActions.swift:30`). Neither carries a run, and neither was changed: both keep working. With no run the server still sends the
interrupt for whatever is open, and refuses only when nothing is open, which is the case where the interrupt does harm and no work is
stopped. iOS shows the 409 message: the chat reports the error and buzzes, and the Live Activity's notice reads "<name> didn't stop"
with the message and "Tap to open the chat." An older web client sends no body and gets the same rule. Naming a run on iOS needs the app to
read the run from the conversation it shows and the Live Activity to carry it in its content state; that is a Swift change for the Mac mini and
is not made here. The web also sends no run when the conversation read names none, such as a turn Hermes runs with no app run, and then gets the
same rule.

## Not exercised

No real Hermes received an interrupt, and the iOS app was not built or run (Linux host); its Stop calls are read, not run. The read and the
interrupt are two RPCs, so a run that ends, or another that starts, between them is still interrupted: Hermes gives a chat session's interrupt no run to
check. The 409 messages were not shown on a phone. A Stop for a background review that outlived its turn, which upstream's interrupt also
cancels, is now refused as nothing running; the app offered Stop only for a running, waiting or blocked conversation, so it never sent one.
