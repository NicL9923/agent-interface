# November 10 home is drawn from the saved roster before bootstrap

Branch `t3/saved-roster`, stacked on `t3/early-bootstrap` at `1485227`, because it removes its copy
through the account-bound key list that branch adds. Checks ran on NicolasLaptop (Fedora, Linux x64,
Node 24.22.2, Chromium from Playwright 1.64.1) on the branch's code as committed. No Python, iOS,
Hermes or server code changed.

## What `main` does

- `src/App.tsx` returns the welcome screen ("Connecting to your household…") until bootstrap
  answers; home (`src/app/Sidebar.tsx`) needs the whole `Bootstrap`.
- Group chats come from `GET /groups` after bootstrap, so they appear after the assistants.
- The browser keeps no roster. It keeps the sign-in hint (#303) and, from `t3/early-bootstrap`, the
  theme.

## Change

- `src/app/saved-roster.ts` keeps `agent-interface:roster`, version 1, written after each connected
  bootstrap and group-catalog answer, only for the account the sign-in hint names and only when it
  changed. It is read once as the page loads, again when another tab changes the hint or the copy,
  and only for the hinted account. Every field is type-checked; a copy of another version, with no
  assistants, or with a field of the wrong kind is not read.
- Fields kept: the person's name (initials) and picture address (account button); each assistant's
  ID, name, avatar and `shared`; favorites, sections (ID, name, assistant IDs), `mainBotId` and
  `mainSuggestionDismissed` (order and placement); each group chat's ID, name and members (member
  ID, profile, handle, display name) for its faces.
- Left out: latest messages and their times, group previews, unread marks, activity, the
  connection, email, model, description, instructions, tools, drafts, tokens and every other
  preference. The copy lists only the assistants bootstrap gave this person.
- `src/App.tsx` draws home from the copy, in the same element tree as the live app, so bootstrap's
  answer redraws the same rows. The saved group chats stay until the catalog answers or fails.
- `Sidebar` in saved mode: "Connecting" (or "Offline", or "Can't connect" after a failed check),
  "Shared assistant" or "Personal assistant" in place of a message, "Group chat with …" in place of
  a preview, no unread mark, date or activity. Account, Search, New, row menus (`BotMenu`) and the
  main assistant suggestion are disabled. Hover prefetch is off.
- A tap on an assistant starts its chat read through `prefetchLinkedChat(id)`, the linked-chat path
  with its account check, and opens the chat once bootstrap answers; the start page does not
  replace a choice made there. Today and group chats wait for bootstrap.
- The copy is in `accountKeys`, so it goes at sign-out, a refused session, a new sign-in and a
  bootstrap for another account, with the hint.
- `.agents/tools/measure-first-load.mjs` also reports the page's summed layout shift.

## Measurements

`node .agents/tools/measure-first-load.mjs --runs 4 --rounds 3 --compare main=DIR,early=DIR,roster=DIR`
(all three loads, 12 each) and `--only worker,warm --runs 6 --rounds 4` (24 each). Saved builds:
`main` at `d6909e4`, `t3/early-bootstrap` at `1485227`, and this branch. Slow 4G, 4x CPU, dark theme
on a light system, desktop width. The machine's load average was 19 to 33.

Roster painted, ms from navigation start, 25th percentile / median:

| Load | main | early-bootstrap | saved-roster |
| --- | --- | --- | --- |
| Worker's cached shell, 24 loads | 653 / 668 | 516 / 840 | 266 / 269 |
| No worker, warm HTTP cache, 24 loads | 812 / 826 | 810 / 987 | 558 / 574 |
| No worker, cold, 12 loads | 5906 / 6070 | 5823 / 6072 | 5592 / 5819 |

- Layout shift: 0 on every load of every build, up to 800 ms after bootstrap answered. The new e2e
  case also measures the swap itself, with a row focused, and requires under 0.01.
- Loads were bimodal on every build, `main` included, with a slow cluster 400 to 600 ms later.
  Chromium traces of 24 branch loads show the same tasks in the same order in both clusters, each
  about twice as long (a 113 ms task took 205 to 235 ms), clustered in time: the machine's other
  load. The 25th percentile is the uncontended figure. The earlier, quieter run on
  `t3/early-bootstrap` put its median at 513 ms against `main`'s 662 ms.
- Cold, the roster still waits for the bundle; the saved copy paints with the bundle's first render.

## Mutants

Each line was broken by hand, `tests/saved-roster-ui.test.ts` run (with `tests/linked-chat-ui.test.ts`
for the linked-chat change), and the source restored. 31 of 32 went red.

| Mutation | Failed |
| --- | --- |
| Saved home never drawn | "is drawn at once…", "is redrawn in place…" |
| No re-read on another tab's change | "leaves the page when another tab signs out while it shows" |
| Saved rooms stand in for another account | "is gone, from the page and the device, when bootstrap answers as someone else", "is gone when bootstrap finds no session…" |
| Saved rooms dropped when bootstrap answers; rooms wiped before the catalog | "is redrawn in place…" |
| Roster not kept; kept from a disconnected bootstrap; kept without a hint for the account; last message kept | "is what home draws, and nothing said in a chat", "is not kept from a bootstrap that could not reach Hermes", "is gone… as someone else" |
| Tap starts no read; start page overrides the tap; linked chat ignores the chosen chat | "opens the chat chosen there once bootstrap answers…" |
| A different element tree for the saved home | "is redrawn in place…" (row and scroller replaced, focus lost) |
| Version, account, empty roster, bot name, portrait source, avatar mode, sections, member profile, account name checks | the matching "is not drawn for…" case each |
| Roster not in `accountKeys` | "is gone when bootstrap finds no session…", "is gone when the person signs out" |
| Hover prefetch, Account, Search, New enabled, no "Connecting", saved room shows "No messages yet" | "is drawn at once…" |
| `BotMenu` opens while disabled | "is redrawn in place…" |
| Saved bots copied whole | "draws none of what a copy should not hold, even when one holds it" |
| Saved rooms copied whole | survived: `Sidebar` hides a saved room's preview and date on its own (that guard's mutant is red), and nothing else reads a room's latest message. Kept so a future reader of `rooms` cannot get one from the copy. |
| e2e: the saved home not drawn, rebuilt | "a returning member's home…" at the first `toBeVisible` |

The first pass had eight survivors. Four were redundant guards and were removed: the render-time
hint check and `!session.auth` in `App` (sign-in shows until a bootstrap succeeds, and the copy is
read only for the hinted account), and the unread and activity checks in `Sidebar` (the copy
carries neither once `savedHome` copies fields one by one). Three were missing assertions, now
added: the disconnected bootstrap lists assistants, the saved rooms stay saved while the catalog
loads, and a saved room never says "No messages yet".

## Not exercised

- Safari, Firefox, an installed home-screen app and a real phone: not run. Phone width was not
  measured; the UI tests run at desktop width.
- A browser signed in before `t3/early-bootstrap` has no sign-in record, so it draws no saved home
  until its next sign-in, at most seven days.
- A session the server ended early still draws its own saved home for the moment before the 401,
  as the linked-chat read does; the 401 then removes it and shows sign-in.
