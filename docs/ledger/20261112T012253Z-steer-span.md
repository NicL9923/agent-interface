## Defect

Release qualification on the production host (`scripts/spike/extension_probe.py:181`, 2026-11-12) found the steer row
unbound: `{'role': 'user', 'text': "Use the second person's public guidance", 'row_id': 15, 'display_kind': 'steer'}`.
The root receipt held `row_id` 14 and `turn_rows` `[14, 16, 17, 18]`; the steer receipt held no row. Hermes reports in
`persisted_turn.row_ids` only rows whose in-memory message carries a committed `_row_id`, and appends a steer mid-turn
without one, so the steer row is never listed. Since #310, `bind_steers` bound only rows in that list, so with real
Hermes no steer bound. A joined send kept the same list less its prompt row, so a joined send that Hermes delivered as
a steer row was missed the same way, and its span would also have started after the steer row.

`TurnHermes` in `tests/hermes_turn_binding_test.py` listed the steer row in `row_ids`, so CI passed.

## Change

- `bind_steers`: a steer's candidates are the user rows with its exact words whose `row_id` lies from the lowest to the
  highest of the root's `turn_rows`. A steering receipt's row must also be typed `display_kind: "steer"`. A joined send's
  need not be, because Hermes writes a redirect taken during a model request as a plain user row; its turn's prompt
  row is never a candidate. Every earlier guard stays: exactly one candidate, the one-second time check, no receipt
  holding the row, no other receipt of the run with the same words. An empty stored list binds nothing, as
  before.
- `keep_joined_turn`: keeps the completion's rows with the turn's `user_row_id` first, instead of leaving it out, so the
  span starts at the turn's prompt and `bind_steers` knows which row to skip. Journals with the older shape were
  written only by unreleased add-ons (#345 is after production's 078906b2).
- Docs: the rule in `docs/HermesCapabilityMatrix.md` and the `bind_steers`, `bind_turn_row` and `keep_joined_turn`
  docstrings.
