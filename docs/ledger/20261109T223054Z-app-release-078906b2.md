# November 9 app release 078906b

Merged at `078906b211f4b0036186ed109c8977fadb635d85`. The release is live at `https://agentui.wildflowersranch.com`,
web build `f200b82b07d5ac2a`, from the archive with SHA256
`0b8a7be1d33d7d82ee3efc3404d290f92f832ed5b52c68c167357a3d46c15a63`. The host build reproduced the local web build.

A fresh qualification receipt was activated with the release. The guarded release tool's no-change preflight passed.
Activation drained idle native work, switched the release and verified original
Google HTTP and fresh WebSockets, the configured Discord connections and the
gateway guard before clearing maintenance. The
[production receipt](../evidence/production-release-078906b2-20261109T223054Z.json) records the result. Hermes remains
at `ed1afb082eb3`. Afterwards the public service worker reported the new
build, API requests required sign-in, the app and Hermes services were active and
maintenance was clear. A signed-in household session was not exercised.

The first qualification run failed before any check ran. Taking its snapshot of the disposable
Hermes source failed with `fatal: unable to read 4473f528eaa733459f9cc7053d08d9e2aeedfae9`,
because the live Hermes checkout `~/.hermes/hermes-agent` on the host was missing 42 blobs of
HEAD's tree, among them `.github/actions/detect-changes/action.yml`. The live checkout is a
promisor partial clone on git 2.43. A code review agent ran git history commands in that
checkout around 14:55 UTC. A promisor pack landed at 14:55:38 UTC and the commit-graph was
rewritten at 14:57:15 UTC, after release c225e83 had qualified at 06:17 UTC. It was our own
agent, not a Hermes job. Hermes kept running from its working tree, but anything that reads
HEAD's objects offline would have failed, as qualification did. A repack of the same checkout
dropped objects the same way on October 14.

The approved repair only added objects. Before it, the checkout's `git status --porcelain`,
HEAD `ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df`, the tracked repair hash
`3cac9383db868b4e7950dad56496410d5bfb81759655edbbb409c1c221e98fee` (which matched the live
deploy configuration), the refs and `.git/config` were recorded. The 42 objects were packed
from a full clone of upstream `NousResearch/hermes-agent` at `ed1afb082eb3` on the Mac mini's
SSD, where all 42 were blobs of that commit's tree. The pack (SHA256
`dcac8345dc8dd4ece4a4bacaeb9ff36dc4081879e88e465dfb71865f1bf4dd23`) was indexed into the
live repository with `git index-pack --stdin`, which hashes every object it stores. The only
change was the new `pack-3c13342ae42a920b12309ab2da337b0c0ad9adc8` with its index and reverse
index. Afterwards, with `GIT_NO_LAZY_FETCH=1`, status, HEAD, the repair hash, refs and config
were unchanged, and `git rev-list --objects --missing=error --no-walk HEAD` found no missing
object.

The second qualification run of the same stage passed at 22:30 UTC with real integration and
host regressions. It included #289's idle compaction probe, which reported that idle
compaction "yielded to every input, committed without changing the app's view, and did not
repeat". It reused the live receipt's `/opt/google/chrome/chrome` for the local-network probe
and confirmed the production source unchanged. The release was prepared with the host's
Node v24.22.2 runtime and a local Node v24.22.2.
