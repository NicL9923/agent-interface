# Remove Hermes runtime and wire native group & vault adapters

- **Date:** 2026-11-25
- **Branch:** `t3/remove-hermes`

## Summary

Removed the Hermes runtime, Python add-on (`src/hermes/`), Hermes upgrade manager/UI (web + iOS), Hermes host qualification/deploy scripts (`scripts/spike/`, `.agents/tools/hermes-*`), and Hermes-only tests. `HarnessRuntime` is now the sole server runtime, with native SQLite-backed adapters for group chats (`src/server/harness/native-groups.ts`) and encrypted bot vault logins (`src/server/harness/native-vault.ts`).

## Protective Test Red Runs

1. **`tests/native-groups-adapter.test.ts` → `src/server/harness/native-groups.ts` (`replyThreadId`)**
   - **Defect caught:** Before adding `replyThreadId: (message) => message.threadId ?? message.id` to `GroupCoordinator` options, a bot reply to a new topic (`threadId: null`) was persisted with `thread_id = NULL`, causing `toEvent` to emit the reply's own `event_id` as `payload.thread_id` instead of the root message's `event_id`.
   - **Red run:** `npx vitest run tests/native-groups-adapter.test.ts` failed on `sends new topics and thread replies, deduplicates by requestId, and emits GroupEvent wire format` (`[2, "message.member", <reply-id>]` vs expected `[2, "message.member", <root-id>]`).
   - **After fix:** 4/4 passed.

2. **`tests/native-vault-adapter.test.ts` → `src/server/harness/native-vault.ts` (`normalizeOrigin`)**
   - **Hand-broken mutation:** Relaxed `normalizeOrigin` to check only `http:` / `https:` protocol, removing the guards against embedded credentials, paths, query strings, and fragments.
   - **Red run:** `npx vitest run tests/native-vault-adapter.test.ts` failed on `rejects malformed logins, invalid origins, bad item IDs, external sources, and unknown bots` (`promise resolved "{ id: 'vault_811ab6084bd0' }" instead of rejecting`).
   - **After restore:** 2/2 passed.
