# November 10 turn events keep a reply streaming across tools

Branch `t3/turn-stream`, from `origin/main` at `2d461e3`. Checks ran on NicolasLaptop (Linux x86_64,
Node 24.22.2). No real Hermes, iOS build or deployment ran, so no production number exists yet.

## What changed

- `?inflight=3` streams: after each structural frame the Hermes runtime reads the running turn itself,
  once per assistant, one read on its way and one queued, only while such a stream is open. The read is
  windowed from the turn's first message (`turnStarts`). Each whole live reply goes as `event: turn`
  with the turn's saved messages, decorated by `shownMessages` (`src/server/conversation-view.ts`),
  which the conversation read now uses too. Growth stays `inflight-delta`.
- Every conversation read and turn event carries `version`, `BOOT:EPOCH:GENERATION`. The web client
  shows a live reply only beside messages of its own version, puts a newer held turn on top of an
  older read, and ignores an older turn.
- A conversation read waits for a turn read on its way, and a turn read waits only for client reads
  asked at the current structural generation, so a client's open is never asked before a turn read's and
  answered after it.
- A live tick that finds nothing to send gives its 250 ms window back.
- `src/server/conversation-view.ts` joined `src/shared/qualification-inputs.json`: it reads runtime
  messages. This branch also changes `hermes.ts` and `conversation-routes.ts`, so the host needs a new
  qualification receipt either way.

## Mutants

Each line was broken by hand, the protecting tests run, and the source restored, by a scratch script.
33 mutants, all killed. One survived at first: queuing a turn read on `tool.start` was masked by the
superseded-read retry, so the tool-start test now supersedes three reads in a row.

- Runtime (`tests/live-turn-runtime.test.ts`): no turn read on a structural frame; none queued on a tool
  start; reads with no follower; a second read beside the first; the queued flag ignored; no retry without
  a queue; waiting for every client read; reading despite a restored snapshot; a client read overlapping a
  turn read; the turn read retrying inside `readConversationNow`; a read versioned at its end; versions
  without the boot; the turn read without the turn's start; steered guidance starting a turn; `after`
  null inside a cut window.
- Stream (`tests/live-turn-stream.test.ts`, `tests/conversation-events.test.ts`,
  `tests/live-turn-timing.test.ts`): `inflight()` without the turn; a change notice resetting a turn
  stream; growth sent across a version change; no follow on open; follow kept after teardown; turn rows
  not decorated; an empty tick spending its window; a turn stream on a runtime without versions;
  `?inflight=1` payloads carrying runtime fields.
- Client (`tests/live-turn-client.test.ts`, `tests/app-ui.test.ts` turn events): boot ignored; epoch
  ignored; placement by `after` ignored; the overlap guard removed; an older turn applied; a live reply
  shown beside another read; a held turn not put on an older read; an unplaceable turn not reloaded; a
  change notice dropping the live reply.

## Not done
