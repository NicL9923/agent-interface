## What changed

Auto joins Normal, Fast and Ultrafast as a conversation speed on the web and iOS pickers and in the
shared `serviceTiers` contract. Hermes's `fast` key accepts `auto` but reports it as `normal` from
`config.get`, and checks the model only for Fast and Ultrafast. The server therefore reads Auto through
a `config.set` status read. The review round below replaced the first design, which probed Fast
before saving Auto. See `HermesCapabilityMatrix.md` for the source lines.

## Review round: GPT-6.1 Sol, head `e10dcb9`

Sol found three issues, each reproduced against copies of the native Hermes functions:

- The Fast probe changed the live session before Auto was saved. A lost acknowledgement or a failed
  restore left the session on Fast, and a restore could overwrite another client's change.
- `config.get` falls back to the profile default when the session pins Normal, so the restore could
  write Fast over a session that was on Normal.
- A status word outside the contract was read as `normal` instead of refused.

Fix: one write per change and no probe or restore. Auto on a model without fast mode runs at Normal
speed, which Hermes allows. Every read goes through the live session's status; `config.get` is used
only when status is unknown (code 4002), and any other status failure is passed on. `cold` reads as
`normal`; any other word is refused as unreadable. The fake now models `config.get`'s profile fallback.

Checks: typecheck and lint clean, full `vitest run` 168 files and 2416 tests passed. Mutants, each red
then restored: status read replaced by `config.get` (4 failed); Cold mapping removed (1); echo check
removed (1); old-Hermes message match removed (1); a Fast probe added back (4); status failures other
than 4002 falling back to `config.get` (1, from the new busy-session test, which first survived).
