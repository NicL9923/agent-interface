# November 10 check-all runs the whole check battery

Branch `t3/check-all-tool`, from `origin/main` at `785f4f2`. Checks ran on Fedora
(Linux x64, Node 24.22.2, Python 3.14.10, ruff 0.17.3, Playwright Chromium) at commit `2ba3626`, which this
entry follows. No application, Hermes, iOS or deploy code changed. The change is
`.agents/tools/check-all` (logic in `check_all.py`), `scripts/precache-plan.mjs` and `e2e/ports.ts`, with
their tests and docs. Nothing was exercised on macOS: the lock uses `flock` and `socket`, which behave the same
there, but no Mac ran it.

## Change

- `.agents/tools/check-all` runs typecheck, lint, ruff, test, build, e2e and py in that order and prints one
  table. It holds a machine-wide `flock` slot for test, e2e and py, and a lock on the e2e app and control port
  pair.
- `scripts/precache-plan.mjs` matches the terminal and remote desktop packages by directory name, so a
  symlinked `node_modules` (Vite records `../../shared/node_modules/...` or an absolute path) no longer fails
  the build.
- `e2e/ports.ts` keeps 4173 without the tool and refuses a malformed `E2E_PORT`.

## Reproduction of the symlink trap

Before the fix, a worktree whose `node_modules` was a symlink to another checkout's failed `npm run build`
with "The build has no terminal or remote desktop chunks to keep out of the install cache." The manifest keys
were `../../../../../../home/nic/.t3/worktrees/agent-interface/<checkout>/node_modules/@novnc/novnc/core/rfb.js`.
After the fix the same worktree builds, and `Built service worker 79a0897ff2877210 with 64 installed files, 31
cached in the background, 3 on first use and 10 never cached.` matches the plain checkout's line exactly.

## Review follow-up: killed runs, stopped runs, Python inputs

Commit `d6186b4` and the commit that records this section, on Fedora (Linux x64, Node 24.22.2, Python 3.14.10,
ruff 0.17.3), after merging `origin/main` at `b41cc54`. Changes are in `.agents/tools/check_all.py`, its README
entry and `tests/check_all_test.py`.

### Changes

- A run killed with SIGKILL no longer frees its heavy slot while its suite runs. `run_process` passes the lock
  descriptors to the check (`pass_fds`), and `Held.release()` closes its copy without `LOCK_UN`, which would
  unlock the shared lock for every holder. Checked on a live e2e run: only `npm run test:e2e` holds them. Node
  does not pass them to Playwright's runner or its web server. That is enough, since npm waits for the runner and
  the runner stops the server when it exits; a server leaked after the runner itself is SIGKILLed is not covered
  by any lock. The docstring now says this.
- Ctrl-C, SIGTERM and `--check-timeout` send SIGINT to the check's group and wait up to 10 s (`STOP_GRACE`) for it
  to be gone, then SIGKILL. A second interrupt during the wait kills at once. The locks free only after the group
  is gone, and `run_process` joins the timeout thread before returning.
- `--py auto` treats `.agents/tools/`, `src/shared/` and `public/voice-previews/` as Python inputs. A test scans
  every Python test for reads of the repository (`load_source`, `ROOT / ...`, `TOOLS / ...`, `ROOT.glob`) and fails
  naming the test when a read falls outside `PYTHON_INPUT_DIRS`. Derivation at run time was rejected: fixtures
  written to a temporary repository use the same names (`package.json`, `src/app.ts`), so a scan cannot tell a
  read from a fixture without the explicit list.
- A pass of test, build, e2e or py whose counts cannot be read shows `counts unknown`; typecheck, lint and ruff
  still show `-` when clean.
- Tests: the port lease and heavy slot release is asserted after an e2e run; `test_py_auto_runs_when_the_diff_touches_scripts`
  uses `--skip` so auto mode really decides; the fake `node` and fake `ruff` exit 97 on any other argv.

## Review follow-up: descriptor numbers, Python-input bases, the holder's pid

Commits `8002083` and `4d3e148` and the commit that records this section, on Fedora (Linux x64, Node 24.22.2,
Python 3.14.10, ruff 0.17.3), after merging `origin/main` at `f6e0090`. Changes are in
`.agents/tools/check_all.py`, its README entry and `tests/check_all_test.py`.

### Changes

- **The locks reach the whole suite tree at descriptor 17 or higher** (`check_all.py`: docstring, `main`,
  `close_inherited_descriptors`, `run_process`). libuv marks descriptors 0 to 15 close-on-exec when Node starts, and
  goes on past 15 only until it meets a closed number. `main` now closes every inherited descriptor above 2 before
  it opens a lock, so the locks are 3 and 4 whatever the launcher left open, and `run_process` raises when an
  inherited descriptor is 16 or more. The docstring and README now say why only `npm` holds the locks. `main` takes
  `close_inherited=False` for the tests that call it in their own process, where closing descriptors would break the
  test runner.
- **The Python-input scan missed reads that did not go through `ROOT`, `TOOLS` or `load_source`**
  (`tests/check_all_test.py`: `repository_reads` and its helpers). Each file's base names now come from its own
  assignments (`NAME = Path(__file__).resolve().parents[k] / "sub"`, `.parent`, `OTHER / "sub"`), resolved to the
  real directory under the repository root, and from `from support import ROOT` (what `support.py` defines).
  Also seen: `.rglob()`, `open("literal")` and `Path("literal").read_text()` style calls. A base that climbs out of
  the repository, or one name given two different paths in a file, is not guessed at (the second raises). The comment
  above `PYTHON_INPUT_DIRS` in `check_all.py` now lists what the scan sees and what it does not. Running the new scan
  over all 47 Python test files found no read outside `PYTHON_INPUT_DIRS`; `scripts/spike/dashboard_contract_test.py`
  now reads `src/hermes/...` as it should, where it used to be treated as reading the repository root.
- **A run killed with SIGKILL named a dead pid as the slot holder** (`check_all.py`: `Held.update_info`,
  `run_process(on_start=...)`, `run_one`). After `Popen`, both the heavy slot and the port pair's lock file are
  rewritten with the check's pid, keeping the rest of their description.

### Tests

- `test_the_locks_stay_below_descriptor_16_whatever_the_launcher_left_open_so_only_npm_holds_them`: a launcher holds
  descriptors 3 to 20, then runs `main`. The fake `npm` is a script run by the real Node. It records which
  descriptors above 2 are lock files, then which a child it spawns holds. Asserts `[3, 4]` for Node and none for the
  child. Skipped when no `node` is on PATH.
- `test_a_lock_descriptor_node_would_pass_on_is_refused_before_anything_starts`.
- `test_a_slot_held_by_a_killed_run_names_the_live_suite_not_the_dead_run`.
- Scan: `test_a_read_through_any_base_name_or_a_relative_literal_is_seen`,
  `test_a_base_that_points_below_the_root_is_read_from_there_and_a_name_means_what_its_own_file_says`,
