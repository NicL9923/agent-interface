# November 2 Household build 18

Build 18 is from commit `0cea55ae01054b0e861a3b864e047d12e68d330e`. That commit is PR #214's build
bump on top of PR #213's chat, routine, secure input, computer handoff and group chat changes.
Build 17 had been uploaded on October 30 without a repository bump, so this build skips to 18.
The [distribution receipt](../evidence/2026-11-02-household-testflight-build-18.json) binds the
signed IPA. Apple confirmed WildBots 1.0 build 18 as installable for both internal Household
testers.

The app environment was privately backed up, and the announced build changed from 17 to 18
before release `release-86fb20b2-20261102T132855Z` activated. The
[native availability check](../evidence/2026-11-02-native-availability-build-18.json) ran against
that release. It verified authenticated bootstrap, native connectivity and build 18, then removed
its temporary operator session.

## Release preparation

The first qualification failed before any check ran. Hermes `6661080238` had renamed native
plugin membership, and PR #215 fixed the helper. The second qualification passed both the real
integration and host regression checks against the live Hermes `6bb377a`. That made it the first
run of PR #213's add-on changes against a live Hermes.

Preparation then refused for two reasons:
- **A leaked gateway agent count.** The messaging gateway counted an agent while the household
  was idle. With the household's okay, `hermes-gateway.service` was restarted.
- **A stale interpreter.** The Oct 30 Hermes update had moved the store interpreter from Python
  3.14.7 to 3.14.9, but the deploy and upgrade configuration still named 3.14.7. The guarded
  tool's gate call crashed, and the retry loop took that crash for a busy refusal.

PR #216 makes the release tooling handle all three problems. The host's `hermes-linux.json` and
`hermes-worker.json` interpreter keys were corrected by hand, with private backups. Issue #217
tracks making the upgrade helper refresh them itself.
